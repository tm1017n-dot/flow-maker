# 業務マニュアル作成ツールへの発展案

更新日: 2026-09-30  
状態: feat/manual-prototype で手順・案内・点検・画像・参考資料・現在版の改訂情報を実装。画像への注釈、資料台帳、過去版管理・Word出力などは次段階。  
前提: Flow Maker v1.0の作図・保存・出力・テーマ切替を維持し、Windows 11でオフライン利用する。

## 1. 目指す使い方

業務全体のフロー図と、各作業の具体的な手順を同じデータで管理する。図で業務の位置を把握し、その作業を選ぶと「何を確認し、どう操作し、どの状態なら完了か」が分かるマニュアルにする。

自治体での引継ぎを想定し、初任者が読む基本手順を先に置く。例外対応や根拠資料は別枠にまとめ、経験者も参照できる構成とする。

既存の補足メモは下書きとして再利用できるが、長いマニュアル本文を図形内に表示しない。マニュアルに含めない図形や、図形に対応しない全体説明も扱う。

## 2. 追加機能と優先順位

| 優先 | 機能 | 内容 | 得られる効果 |
| --- | --- | --- | --- |
| 最優先 | 作業ごとの手順書 | 目的、事前準備、入力資料、操作手順、確認項目、完了条件、注意事項、例外対応 | 図から具体的な作業方法まで説明できる |
| 最優先 | 章立て・掲載順・手順番号 | 章・節、掲載／非掲載、並べ替え、固定の手順番号。概要・用語・問い合わせ先などの共通章も追加 | 読みやすい文書を組み立てられる |
| 最優先 | フローと本文の連動 | 作業を選ぶと対応する手順を開く。本文から図へ戻る。担当・作業名・分岐条件は共通データを参照 | 二重入力と更新漏れを減らす |
| 最優先 | 閲覧用画面・出力 | 目次、全体図、基本手順、例外対応、参考資料のプレビュー。持ち運べるHTMLと複数ページPDF | 作成したマニュアルを職員へ渡せる |
| 次段階 | 画像・画面キャプチャ | 手順への画像挿入、説明文、強調枠・番号、画像サイズ調整、差し替え | システム操作を説明しやすくする |
| 次段階 | 帳票・システム・根拠資料の一覧 | 関連する様式、システム、要綱・通知などを登録し、複数手順から参照 | 必要な資料を探しやすくする |
| 次段階 | 記載漏れの点検 | 手順未記入、完了条件未記入、番号重複、削除された参照、根拠資料の確認日など | 引継ぎ前に不足を確認できる |
| 次段階 | 文書情報・改訂履歴 | 所管部署、作成者、版、更新日、変更理由、確認者、見直し予定日。確定時の版を保存 | 古い手順との区別と更新管理ができる |
| 後段階 | テンプレート・検索 | 受付・審査・通知などのひな型、全文検索、担当・帳票・システム別の絞り込み | 複数業務で作成・参照しやすくする |
| 後段階 | Word出力 | 図・本文・画像を含む編集可能なDOCX | 庁内の様式調整や既存文書との統合ができる |
| 後段階 | 複数フロー・共通手順 | 親子フロー、別業務から共通手順への参照、複数業務のマニュアル集 | 大きい業務や共通作業を管理できる |

「最優先」は、実際に読めるマニュアルを作成・保存・再編集・配布できる最小の一式。画像以降は、その一式が成立してから追加する。

## 3. 作業の入力項目

| 区分 | 項目 | 入力例 |
| --- | --- | --- |
| 基本 | 作業名・担当 | 申請内容を確認する／窓口担当 |
| 基本 | 作業の目的 | 申請要件と必要書類の充足を確認する |
| 基本 | 事前準備・入力資料 | 申請書、添付書類、確認用一覧 |
| 基本 | 実施手順 | 1. 申請内容を照合する 2. 添付書類を確認する |
| 基本 | 確認項目 | 記入漏れ、添付不足、対象要件 |
| 基本 | 完了条件・成果物 | 不足の有無を判断でき、確認結果を記録している |
| 基本 | 次の作業・分岐条件 | 不足ありなら案内、不足なしなら審査担当へ渡す |
| 補足 | 注意事項・例外対応 | 通常と異なる場合の対応と相談先 |
| 補足 | 帳票・システム・根拠資料 | 使用様式、利用画面、参照資料、確認日 |
| 補足 | 画像 | 操作画面の説明付きキャプチャ |

必須項目は業務の種類に応じて設定できるようにする。初期値では目的・実施手順・完了条件を中心に点検し、すべての欄を無理に埋める運用を避ける。

## 4. 画面構成

上部に「フロー」「手順」「プレビュー」の切替を置く。

- **フロー**: 現在の作図画面。作業を選び「手順を編集」で本文を開く。手順の記載有無が分かる表示を付ける。
- **手順**: 左に章・作業の一覧、中央に広い入力領域。基本手順を先に、例外・参考情報を折りたたんで置く。長文入力を現在の細いプロパティ欄に押し込まない。
- **プレビュー**: 編集用のボタンを省き、目次・全体図・手順書を読む画面。図と手順を相互に移動できる。
- **出力**: フロー図1ページの出力と、マニュアル全体の出力を分ける。マニュアルはA4縦・複数ページを基本とし、全体図は別ページへの配置も選べる。

作成画面はライト／ダークに対応し、印刷・配布用の初期値は白背景とする。

## 5. 図と文書を結び付ける際の設計

### 手順の順序

図形の座標から文書の掲載順を決めない。分岐・合流・差戻しがあるため、フローは必ずしも一列の順番にならない。

章と掲載順は利用者が指定する。初期の並びを提案する場合も、確認・修正できるようにする。固定の手順番号（例: S010）と表示順は別に持ち、章の並べ替えで参照先が変わらないようにする。分岐は「条件 → 対応する手順」として本文に表示する。

### データの共通化

- 図形IDを手順との対応付けに使い、名称変更や移動でリンクが切れないようにする。
- 作業名・担当・接続・分岐条件は現在のフローから参照し、手順側に同じ内容を別々に保存しない。
- 実施手順・確認項目・完了条件などはマニュアル側に追加する。
- 図形の削除時は、対応する手順を削除するか、図との対応を外して残すか確認する。本文を黙って失わない。
- 既存の補足メモを本文へ移す操作を用意する。フロー用JSONだけを扱う旧版では追加情報を失う可能性があるため、新しい保存形式は別バージョンで扱う。

### 保存と画像

最初は、マニュアル情報を含む新形式のJSONを1冊ごとに保存する。旧フローJSONは読み込んでマニュアルを新規作成でき、元ファイルはそのまま残す。

画像を導入する段階では、画像も含めて持ち運べる保存形式を整える。少数画像の埋め込みから始めるか、JSONと画像をまとめたZIPにするかを、実測のサイズ・保存速度で選ぶ。閲覧用HTMLは画像も含めて自己完結させ、別PCで画像が欠けないようにする。ファイル名やパスだけを保存して持ち運べることにはしない。

画像処理・ZIP・DOCXにライブラリを使う場合も、アプリに同梱し、実行時の外部通信を必要としない構成を維持する。

## 6. 実装する順序

1. **手順の構造化**: 作業ごとの入力欄、新形式の保存・読込、旧JSONの取込。
2. **文書の組み立て**: 共通章、章立て、掲載順、固定番号、図と本文の相互移動。
3. **配布までの完成**: 閲覧プレビュー、自己完結HTML、複数ページPDF。ここで文章中心の最小版を確定。
4. **説明の充実**: 画像、帳票・根拠資料、記載漏れ点検。
5. **継続管理**: 改訂履歴、検索、テンプレート。
6. **大規模利用への展開**: Word出力、複数業務・共通手順。

共同編集、サーバー保存、正式な承認ワークフロー、AIによる自動執筆は、必要性と利用環境を確認してから別途検討する。初期の実装範囲には含めない。

## 7. 最小版の完了条件

- 現在のフローJSONから、作業ごとの手順を作れる。
- 名称・担当・分岐を変えると、手順の関連表示にも反映される。
- 分岐・差戻しがあっても、章と掲載順を明示して文書にできる。
- 図に対応しない概要・用語などの章を作れる。
- 保存して別PCで開いても、本文と図の対応が維持される。
- 配布用HTMLをオフラインで読め、複数ページPDFの本文が欠けない。
- 現在の作図・JSON・PNG/PDF出力に回帰がない。

実装は確定済みv1.0から作業用ブランチで進め、作図版の基準を残すことを推奨する。初回試作の内容と確認範囲は [manual-prototype.md](manual-prototype.md) を参照する。


## 今回の実装と今後の区別

画像の埋め込み・説明文、手順別の資料リンク、操作案内・点検、手順複製、対応切れの再接続、現在版の作成者・確認者・更新日・改訂内容を追加した。画像の強調枠や番号描画、共通資料台帳、過去版の差分管理、正式な承認は含まない。確認者の記載を承認済みの判定に使わない。

点検は必須欄などの機械的な確認で、業務手順の妥当性を保証しない。ブラウザ・実機での印刷品質は未確認のため、実運用版の確定前に [manual-prototype.md](manual-prototype.md) の操作確認を行う。
